# 大队列的参数学习与独立验证

在看差异结果前，按患者分成学习队列和独立验证队列。技术重复、同一患者不同部位或时间点的样本全部留在同一队列。每份清单中的样本都填去标识化的 `patient_id`。程序保留 `sample_id` 做版本配对，按种子→样本→患者求均值。只有每例样本确实来自不同患者时，才省略 `patient_id`。程序通过配置识别组别，研究者仍需检查两个清单的患者交集和受检人群差异。

## 学习队列

```json
{
  "statistics": {
    "primary_pairs": [],
    "margins": {},
    "upstream_loss_margin": null
  }
}
```

`primary_pairs: []` 保留描述性差异及区间。可以检查候选窗口、种子抽取数量、背景模式和重跑预算对稳定性的影响，记录失败及不可评价比例。改变任一条件都用独立输出目录。既有种子是研究输入，候选保留率只适用于这些区域。按测序平台、深度、参考策略、有无扩增信号等预先计划分层。不要通过事后忽略失败或删除分歧病例获得更高一致性。

## 独立验证队列

选择真正面对的版本对。`statistics.primary_pairs` 可以是 `"reference"`（只对固定参考的版本对作判定），或一组无序对，例如 `[["suite-1.6.1", "suite-1.6.2"]]`。省略该设置会沿用全配对判定。历史两两比较仍可保留为描述性结果。

选择界值时先写清结果将用于什么。对照版本中观察到的扩增被漏掉，会改变候选复核、样本纳入还是区段提取？将可容忍后果分别翻译成检出失配、标签不一致、区段差异和分类区段差异的上限。用学习队列估计预期差异和可评估比例，结合研究用途与可能损失设定界值。上游 `upstream_loss_margin` 容忍的是已知候选的丢失，`min_seed_overlap` 则定义区段匹配规则。两者的单位和决策作用不同。

预先锁定这些设置、患者单位、比较版本、运行范围和结论指标。按独立患者而非种子数规划样本量。对一个 `[0,1]` 损失，在预期平均损失 `m` 小于界值 `δ` 时，当前保守判定的粗略最低规模为 `n > log(1/alpha_eff)/(2(δ-m)^2)`，其中 `alpha_eff` 是报告里的校正后单侧错误率。该式仅说明在给定观察均值时置信界可能有多宽。实际需要考虑缺失、效应波动和多个来源分层。对正式设计，应以拟定队列的效应和可用性做功效或模拟评估。独立验证后原样保留所有结果，记录配置和软件版本。[统计细节](statistical_methods.md)

## Suite 1.6.1 下采样重复性

Suite 1.6.1 更新了 AA 下采样的可重复性。为检验该改动，单独建立 `with_bam` 试验，纳入 Suite 1.6.0 和 1.6.1，锁定同一 BAM、参考、种子、求解器和正值 `aa_parameters.downsample`。根据测序深度在分析前选择能实际触发下采样的值。用新的输出目录独立重复运行，避免续跑重用结果。比较同版本重复间的检出、分类区段、graph/cycles及日志中的实际下采样；跨版本比较单独报告。默认 `downsample=-1` 的有限区域研究仍可作为另一个条件。[上游发布说明](https://github.com/AmpliconSuite/AmpliconSuite-pipeline/releases/tag/v1.6.1)
